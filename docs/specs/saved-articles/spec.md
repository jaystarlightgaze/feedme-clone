# 저장한 글

로그인한 사용자가 변환한 글은 자동으로 저장되고, '저장한 글' 목록에서 다시 열어 보거나 내보내거나 삭제할 수 있습니다.

## Linked sources

- [docs/decisions/export-actions.md](../../decisions/export-actions.md): 상세 화면의 프롬프트 선택과 내보내기 줄 배치, 각 버튼에 들어가는 내용은 홈과 같이 이 계약을 따릅니다.

## User-visible outcomes

1. 로그인한 사용자가 URL을 변환하면 따로 누르지 않아도 그 글이 저장되고, 저장됐다는 표시를 봅니다.
2. 같은 글을 다시 변환하면 목록에 중복이 생기지 않고, 기존 항목이 최신 내용으로 바뀌어 맨 위로 올라옵니다.
3. 헤더의 '저장한 글'에서 내가 저장한 글을 최근 변환 순으로 봅니다.
4. 목록에서 글을 열면 저장해 둔 본문을 다시 보고, 홈과 같은 방식으로 복사·다운로드·LLM 열기를 합니다.
5. 목록이나 상세에서 글을 하나씩 삭제합니다.

## Scope

### 자동 저장
- 로그인한 상태에서 변환이 성공하면 그 변환한 글(원문 주소, 제목, 저자, 도메인, 본문 Markdown)을 현재 사용자의 저장한 글로 남깁니다. 저장 버튼은 따로 두지 않습니다.
- 원문 주소가 이미 저장한 글과 같으면 새 항목을 만들지 않고, 그 항목의 내용과 저장 시각을 이번 변환 결과로 바꿉니다.
- 변환이 실패(입력 오류, 가져오기 실패, 차단, 본문 없음)하면 아무것도 저장하지 않습니다.
- 저장에 성공하면 내보내기 줄 아래에 "저장한 글에 담았어요 · 저장한 글 보기"를, 기존 항목을 갱신했으면 "이미 저장한 글이라 최신 내용으로 바꿨어요 · 저장한 글 보기"를 보여 줍니다. '저장한 글 보기'는 목록으로 갑니다.
- 저장에 실패해도 변환 결과와 내보내기는 그대로 쓸 수 있습니다. 같은 자리에 "저장하지 못했어요. 변환 결과는 그대로 쓸 수 있어요 · 다시 저장"을 보여 주고, '다시 저장'은 같은 결과로 저장을 다시 시도합니다.
- 비로그인 상태에서는 변환과 내보내기가 지금처럼 동작하고 저장하지 않습니다. 결과가 있으면 같은 자리에 "로그인하면 변환한 글이 자동으로 저장돼요 · 로그인"을 보여 줍니다. '로그인'은 로그인 화면으로 가고, 로그인을 마치면 홈으로 돌아옵니다.
- 이전에 변환한 결과를 소급해 저장하지 않습니다. 로그인한 뒤 새로 변환한 글부터 저장됩니다.

### 헤더
- 모든 화면의 헤더에 '저장한 글' 링크를 둡니다.
- 헤더의 기존 계정 링크(비로그인 '로그인', 로그인 '설정')는 그대로 두고, 그 옆에 '저장한 글'을 더합니다.

### 저장한 글 목록
- 로그인한 사용자만 볼 수 있습니다. 비로그인으로 열면 로그인 화면으로 보내고, 로그인 뒤 목록으로 돌아옵니다.
- 현재 사용자의 저장한 글만, 마지막으로 변환한 순서(최신이 위)로 모두 보여 줍니다.
- 항목마다 제목, 도메인, 저장 시각을 보여 줍니다. 제목은 두 줄을 넘으면 말줄임합니다. 항목을 누르면 상세로 갑니다.
- 페이지 제목 아래에 개수를 "N개 · 최근에 변환한 순서"로 보여 줍니다.
- 저장한 글이 없으면 빈 상태("아직 저장한 글이 없어요", "로그인한 상태로 변환한 글이 여기에 자동으로 모여요.")와 홈으로 가는 '글 변환하러 가기' 버튼을 보여 줍니다.
- 각 항목 끝에 삭제 버튼을 둡니다.

### 저장한 글 상세
- 저장한 시점의 내용을 보여 줍니다. 원문을 다시 가져오지 않습니다.
- 위에서부터 '← 저장한 글' 링크와 저장 시각·삭제 버튼, 프롬프트 선택, 내보내기 줄(복사하기, .md 다운로드, ChatGPT로 열기, Claude로 열기), 결과 카드 순서로 둡니다. 프롬프트 선택(다중 선택 포함)과 내보내기는 홈과 똑같이 동작합니다.
- 다른 사용자의 글이나 없는 글을 열면 찾을 수 없다는 화면을 보여 주고 내용은 노출하지 않습니다.

### 삭제
- 목록의 삭제 버튼과 상세의 '삭제' 버튼은 확인 다이얼로그("저장한 글을 삭제할까요?", 글 제목과 되돌릴 수 없다는 안내, 취소·삭제)를 엽니다.
- 취소하거나 바깥을 누르거나 Esc를 누르면 아무것도 지우지 않습니다.
- 삭제하면 항목이 목록에서 사라지고 "삭제했어요" 알림을 보여 줍니다. 상세에서 삭제하면 목록으로 돌아갑니다. 마지막 항목을 지우면 빈 상태로 바뀝니다.

## Acceptance criteria

1. 로그인한 상태에서 URL을 변환하면 내보내기 줄 아래에 "저장한 글에 담았어요"가 보이고, 목록 맨 위에 그 글이 제목·도메인·저장 시각과 함께 나온다.
2. 같은 URL을 다시 변환하면 "이미 저장한 글이라 최신 내용으로 바꿨어요"가 보이고, 목록 개수는 그대로이며 그 글이 맨 위에 있다.
3. 변환이 실패하면 목록에 아무것도 추가되지 않는다.
4. 비로그인 상태에서 변환하면 결과와 내보내기는 그대로 동작하고, "로그인하면 변환한 글이 자동으로 저장돼요" 안내가 보이며, 아무것도 저장되지 않는다.
5. 비로그인으로 `/saved`나 저장한 글 상세를 열면 로그인 화면으로 가고, 로그인 뒤 원래 화면으로 돌아온다.
6. 목록에서 글을 열면 저장 시점의 제목·저자·도메인·본문이 보이고, 복사하기·.md 다운로드·LLM 열기가 홈과 같은 내용으로 동작한다.
7. 사용자 A가 저장한 글은 사용자 B의 목록에 나오지 않고, B가 A의 글 상세 주소를 직접 열어도 내용이 보이지 않는다.
8. 목록과 상세에서 삭제를 확인하면 글이 사라지고 "삭제했어요"가 보인다. 취소하면 그대로 남는다. 상세에서 지우면 목록으로 돌아간다.
9. 저장한 글이 하나도 없으면 목록에 빈 상태와 '글 변환하러 가기' 버튼이 보인다.
10. 저장이 실패해도 변환 결과와 내보내기는 쓸 수 있고, 저장 실패 안내와 '다시 저장'이 보이며, '다시 저장'이 성공하면 저장 표시로 바뀐다.
11. 390px 폭에서도 목록·상세·다이얼로그의 내용과 버튼이 가려지지 않는다.

## Settled constraints

- **변환할 때 자동 저장한다.** 사용자가 저장 버튼 방식 대신 직접 골랐습니다. 훑어본 글도 쌓이므로 삭제를 같은 범위에 넣었습니다.
- **원문 주소마다 한 항목만 둔다.** 자동 저장이라 같은 글을 여러 번 변환하면 중복이 금방 쌓이기 때문입니다. 다시 변환하면 내용과 저장 시각을 바꾸고 맨 위로 올립니다. 예전 버전은 남기지 않습니다.
- **개별 삭제를 넣는다.** 자동 저장으로 쌓이는 목록을 정리할 방법이 필요해서입니다. 삭제 전에 확인합니다.
- **저장한 글은 소유자만 읽고 지운다.** 다른 사용자의 글은 목록·상세 어디에도 노출하지 않습니다.
- **상세는 저장 시점 스냅샷을 보여 준다.** 원문이 바뀌거나 사라져도 저장한 내용을 다시 볼 수 있어야 하기 때문입니다.
- 저장소는 이미 붙어 있는 Supabase(인증·DB)를 씁니다. 새 서비스는 들이지 않습니다.

## Assumptions

에이전트가 정한 기본값이며 언제든 바꿀 수 있습니다.

- "같은 글"은 변환 결과의 원문 주소(리다이렉트를 따라간 최종 주소)가 문자 그대로 같은 경우입니다. 쿼리나 끝 슬래시 정규화는 하지 않습니다.
- 저장 시각은 목록에서 상대 표기("방금 전", "3시간 전", "어제", 그보다 오래되면 날짜), 상세에서 날짜와 시각 전체로 보여 줍니다.
- 목록에는 검색, 정렬 변경, 페이지 나누기가 없습니다.
- 삭제 후 되돌리기는 없고, 확인 다이얼로그로 대신합니다.
- 저장 표시 문구와 아이콘은 프로토타입대로 둡니다.
- 상세의 프롬프트 선택은 저장하지 않으며 화면을 떠나면 초기화됩니다.

## Off-limits

- 변환 자체(가져오기, 본문 추출, 오류 구분)는 바꾸지 않습니다. [content-extraction](../../decisions/content-extraction.md)이 관할합니다.
- 내보내기 버튼의 구성·배치·내용은 바꾸지 않습니다. 상세는 홈의 것을 그대로 씁니다.
- 로그인·회원가입·설정 화면의 동작과 헤더의 계정 링크는 이 작업에서 바꾸지 않습니다.
- 공개 배포 남용 방지는 [follow-up](../../follow-ups/public-deploy-abuse-limit.md)에서 따로 다룹니다.

## Remaining risks

- 사용자당 저장 개수에 한도가 없습니다. 본문 Markdown을 통째로 저장하므로 오래 쓰면 목록과 저장 용량이 커집니다. 첫 버전에서는 받아들입니다.
- 원문 주소 문자열 그대로 비교하므로, 같은 글이라도 추적용 쿼리가 다르면 별도 항목이 됩니다.
