# 본문 추출

## Decisions

- 웹 페이지 본문 추출과 Markdown 변환은 `defuddle` npm 패키지(`defuddle/node`와 DOM 구현)로 합니다.
- 페이지는 서버에서 가져옵니다. 브라우저에서 대상 페이지를 직접 가져오지 않습니다.
- 서버는 받은 HTML만 파싱하고 JavaScript는 실행하지 않습니다. 스크립트로 내용을 그리는 페이지는 "본문 없음"으로 처리합니다.

## Boundaries

- 호스티드 `defuddle.md` API를 쓰지 않는다는 결정입니다. `defuddle`의 옵션과 DOM 구현(linkedom, jsdom) 선택까지 고정하지는 않습니다.
- 서버가 대신 가져오는 주소에서 사설망·로컬·링크로컬 주소는 차단합니다. 공개 배포에 필요한 추가 방어는 이 결정에 포함되지 않습니다.

## Why

`defuddle` 라이브러리 사용은 사용자가 필수로 정했습니다. 호스티드 API를 쓰면 외부 서비스에 의존하게 되고 요청 한도와 과금이 붙습니다. 브라우저에서는 CORS 때문에 임의의 페이지를 가져올 수 없으므로, 가져오기는 서버에서만 할 수 있습니다.

## Reconsider when

- 실제 사용에서 SPA처럼 스크립트가 필요한 페이지의 추출 실패가 주된 불만이 될 때(헤드리스 브라우저 렌더링 검토)

## Still-rejected alternatives

- 호스티드 `defuddle.md` API — 외부 의존과 요청 한도가 생깁니다. 서버 운영을 할 수 없는 환경으로 옮길 때만 다시 봅니다.
- 헤드리스 브라우저로 렌더링한 뒤 추출 — 범위와 운영 비용이 커서 첫 버전에서 제외했습니다.
